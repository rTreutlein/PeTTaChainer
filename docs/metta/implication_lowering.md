# One implication lowering

Merge 1b continues merge 1's source-storage deletion. Public positive judgments
and executable CTVs use ordinary implication keys. The hypothetical worlds
that calculate a judgment remain private: assumptions, consequent metadata,
borrowing restrictions and producer lifetime still apply. The public API and
its signatures are unchanged.

## One source and one set of producers

An implication has three supports: its immutable stated value, a judgment of
its consequent under its antecedent, and instance evidence or the existing
refined `RuleTruth` parameter. Both query plans call `judgment-query-side`;
the internal CTV plan calls it for each polarity. Sources retain both
executable branches and their original proof.

`compile-rule` stores one source TV per statement/proof identity. A CTV is not
also stored as an STV. A quantified source keeps the same value at its separate
canonical statement shape. The stored-source collector and the copies that
projected indexed rule producers into positive producers are deleted. The
runtime reads the original facts and original computed producer values.

Root discovery finds stored keys without binding the query's proof or TV to
the raw stored value. Read policy applies afterward. This preserves open,
ground, negated and quantified zero-budget source judgments, including sources
added through `add-to-kb`. Repeating an identical CTV source remains legal.

## Read policy preserves provenance

`sk-read-fact` is the typed boundary between full CTV storage and a positive
STV read. An executable conversion of a stated STV is not another positive
source: an indexed source lookup compares the complete statement, scope and
step proof up to alpha identity, without binding the caller. The stated
positive value already supplies that source. This also prevents a reconciled
executable branch from replacing the stated positive judgment.

`sk-read-value` applies that policy without changing evidence or dependencies.
Ordinary, conditioned, compatible and waiting reads share it. A positive view
of a forward copy or frozen summary retains that record's original provenance;
it is never a new observation. Live CTV producer values can therefore answer
positive reads directly, including zero-budget reads after a forward run.

Positive reads select their values before merging, as derived-statement
applications select rule-derived producers. An STV and a CTV are value
policies over one key, not different KBs. Ordinary source evidence takes the
actual KB directly. `contextualize-rule-premise` scopes hypothetical reads but
no longer redirects positive implication premises into another KB.

Scaffold reuse still checks exact statement shape up to alpha renaming,
proof/TV constraints and lifetime. Permanent consumers cannot borrow temporary
assumptions. Class-link producers remain permanent at the ordinary link key;
the installer compiles their sample/fold additions directly.

## Samples and executable assumptions

STV and CTV consumers share one two-branch instance tally and one sample
population. A positive-only instance result projects after that tally and
requires positive evidence; negative-only samples cannot invent a positive
answer. Full consumers retain the learned-rate formulas. The separate
positive-only finish is deleted, so the same sample cannot revise itself
through two finish policies.

An Assuming implication is an executable seed, not support for its own
judgment. Open context bookkeeping retains the seed and its `ContextRule`
guard, so applications wake and execute. STV judgment reads reject that seed
and select admissible values before merging, rather than consuming an open
merge containing it. Private hypothetical assumptions retain their scoped
behavior. Both original semantic blocker tests keep their original answers.

Positive implication and quantified judgments are never materialized as world
facts, and their hypothetical premise proofs are not published in MAIN.
Ordinary materialization is unchanged.

## Scheduling and validation

`term-confidence` reads ordinary premise TV confidence without the former
open-proof multiplier. CPU policies, including zero search priority for
settled steps, remain unchanged. The relaxed gate permits scheduler and proof
presentation changes with unchanged test TVs; duplicate evidence and changed
logical answer sets still block. `MERGE1B_REPORT.md` records moved pins, token
counts, symbol audit, final gates and finite-budget benchmark differences.

Exists claim/witness folds, Boolean-event conditional planning, compound
outputs and connective canonicalization retain their existing semantics.
